## Why v1.4.0

The post-v1.3.8 mainline contains a substantial backward-compatible product expansion rather than only patch-level maintenance. The implementation includes the V1.5 Human + Agent operating model, governed Agent templates/workforce/instances, Agent evaluation and identity/access governance, canonical Agent-to-Run binding, governed tool execution, workforce governance APIs and UI, plus significant frontend/toolchain hardening.

The current breaking-change audit did **not** establish a backward-incompatible change to the existing public API contract. Under Semantic Versioning, backward-compatible functionality belongs in the MINOR version, while a MAJOR bump requires a backward-incompatible public API change.

Therefore the candidate target is `v1.4.0`, not `v2.0.0`.
