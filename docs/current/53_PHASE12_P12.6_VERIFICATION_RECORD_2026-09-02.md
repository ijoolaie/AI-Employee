# Phase 12 — P12.6 Exportable Verification Record

Date: 2026-09-02

## Purpose

P12.6 adds a tenant-scoped, authorization-aware export surface for completed
Test Center runs. The exported JSON is an engineering/product verification
record suitable for local delivery and future external acceptance workflows.

## Export Contract

Endpoint:

`GET /api/v1/test-center/runs/{run_id}/verification-record`

Authorization:

- Uses the existing `run.read` permission through `RunReadContext`.
- Resolves the run, test definition and artifacts with the authenticated
  tenant boundary.
- A run from another tenant is not exportable.

Completed-run boundary:

- Only `passed` and `failed` runs can produce a verification record.
- Queued, running, cancelled and expired runs are rejected.

## Record Contents

The record includes:

- record type and schema version
- explicit engineering/product evidence boundary
- non-acceptance statement
- tenant identity
- run identity and lifecycle timestamps
- actor/executor identity and correlation ID
- structured result and evidence
- runtime version
- migration identity
- Git SHA
- test definition identity, category and acceptance requirements
- tenant-scoped artifact references, checksums, sizes and metadata

Test fixtures are deliberately excluded from the exported record to minimize
unnecessary exposure of test inputs.

## Integrity and Safety

- Export is read-only with respect to the Test Center run.
- No external storage or provider dependency is introduced.
- Existing audit logging records the export action.
- The record does not claim Vendor, Reseller, Customer or external production
  acceptance.
- The canonical v1.3.2 release identity is not modified.

## Evidence Boundary

Phase 12 evidence remains engineering/product evidence only. External
acceptance must be established by the applicable future workflow and is not
implied by this export.
