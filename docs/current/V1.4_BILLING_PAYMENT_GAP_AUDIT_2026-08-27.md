## Important implementation notes

### Stripe boundary

The repository contains real Stripe Checkout, Billing Portal, webhook verification, subscription-event processing, refund and reversal adapter calls. The adapter is explicitly fail-closed when Stripe configuration is absent.

### Refund/reversal

Refund requests enforce tenant/provider ownership, currency consistency and tenant-scoped idempotency. Refunds use Stripe idempotency keys. Reversal is implemented as cancellation of an eligible uncaptured PaymentIntent. Lifecycle state is persisted in `PaymentRefund` and linked to a `BillingEvent`.

The ORM metadata column remains named `metadata`, while the Python attribute is `refund_metadata` to avoid SQLAlchemy's reserved Declarative attribute name.

### Verification boundary

Repository tests prove local contracts and behavior. They do **not** prove a real Stripe account, live Checkout, real webhook delivery, real payment/refund, or production customer lifecycle.

## Current decision

**Do not create another generic billing implementation PR.**

The next work should be external/runtime certification and targeted hardening only where evidence exposes a concrete gap.
